93.1 ePaper Radio

FM 튜너가 없는 보드로 만든 FM 라디오. 방송사 스트림을 Wi-Fi 로 받아 온보드 스피커로 내보내고, 200×200 전자종이에는 실제 서울 FM 주파수를 쓴 아날로그 다이얼을 그린다. 같은 펌웨어를 M5StickS3 에도 올린다. 사용법 · 프로그램 구조 · 기술 사양.

이게 무엇인가

이 보드에는 FM 튜너 칩이 없다. 88~108MHz 를 받는 회로가 아예 없고 ESP32-S3 의 무선은 2.4GHz Wi-Fi/BLE 전용이라, 보드 단독으로 전파를 수신하는 것은 물리적으로 불가능하다.

그래서 이 펌웨어는 방송사 HLS 스트림을 Wi-Fi 로 받아 재생한다. 나오는 소리는 실제 FM 방송 그대로이고, 화면에는 각 채널의 진짜 서울 FM 주파수를 쓴 아날로그 다이얼을 그린다. 겉보기와 조작감은 FM 라디오이되, 신호는 인터넷에서 온다.

진짜로 전파를 받으려면 RDA5807M 같은 I2C FM 튜너 모듈을 확장 헤더에 물려야 한다. 블루투스 스피커도 불가능하다 — A2DP 는 Classic Bluetooth 위에서만 동작하는데 ESP32-S3 는 BLE 전용이다.

주의

라디오 모드에서 채널을 넘기려다 2초를 넘기면 Wi-Fi 설정 포털이 열린다. 포털은 5분 뒤 저절로 닫히고 원래대로 돌아오니 잘못 열었어도 기다리면 된다.

화면 읽는 법

라디오 화면 상단 왼쪽은 시계, 오른쪽은 Wi-Fi 신호 세기와 배터리 잔량이다. Wi-Fi 막대는 장식이 아니라 실제 RSSI 를 반영한다 — −60dBm 이상 3칸, −70 이상 2칸, −80 이상 1칸.

가운데 큰 숫자가 주파수, 그 아래가 채널명, 그 아래 다이얼의 바늘이 현재 위치다. 맨 아래 줄은 상태(ON AIR, BUFFERING, TUNING, PAUSED, ERROR)와 비트레이트, 배터리 전압이다.

세 가지 모드

PWR 을 길게 누를수록 더 깊이 잔다는 한 가지 규칙으로 묶여 있다. 돌아올 때는 어느 상태에서든 PWR 이다.

시계 모드

1분마다 잠깐 깨어나 시각·날짜·온습도·배터리를 갱신하고 다시 잠든다. Wi-Fi 는 절대 올리지 않는다 — 그게 전력의 대부분이라 올리는 순간 시계 모드의 의미가 없어진다.

갱신은 부분 갱신이라 깜빡이지 않는다(0.36초). 잔상 제거용 전체 갱신은 하루 한 번만 한다.

딥슬립

화면이 그 시점에서 멈춘다. 멈춘 시계는 고장난 시계로 보이므로 시각과 온습도를 지우고 사진으로 화면을 채운다. BOOT 를 누르면 그 순간 측정한 값을 AT HH:MM 과 함께 보여주고, 한 번 더 누르면 사진으로 돌아온다.

KBS · MBC · SBS 의 스트림 주소에는 만료되는 서명이 붙어 있어, 선국할 때마다 방송사 API 를 다시 호출해 새 주소를 받는다. 나머지는 고정 주소다.

화면에 쓸 한글 폰트가 없어 채널명은 로마자로 적혀 있다.

채널이 안 나올 때

화면에 NO STREAM 이 뜨면 방송사 API 가 응답하지 않은 것이다. 기기 문제가 아니며 BOOT 로 다른 채널로 넘기면 된다. 8초마다 자동으로 재시도하므로 방송사 쪽이 복구되면 알아서 다시 붙는다.

Wi-Fi 설정

접속 정보는 기기 안(NVS)에 저장된다. 펌웨어에 박아 둔 값은 저장된 게 없을 때의 초기값으로만 쓰이므로, 다른 곳에 들고 가도 재빌드 없이 바꿀 수 있다.

설정 화면은 두 경우에 열린다 — 부팅할 때 Wi-Fi 접속을 세 번 연달아 실패하면(한 번에 12초씩 기다린다) 자동으로, 또는 라디오 모드에서 BOOT 를 2초 이상 눌렀을 때. 공유기가 아직 안 올라온 정전 직후 같은 상황 때문에 한 번 실패로는 열지 않는다.

다른 보드: M5StickS3

같은 펌웨어가 M5Stack M5StickS3 에서도 돈다. MCU (ESP32-S3-PICO-1-N8R8)도 오디오 코덱(ES8311)도 같고 I2C 핀까지 우연히 같아서, 스트리밍 · 선국 · 채널 목록은 손대지 않고 그대로 쓴다.

근본적으로 다른 것은 화면이다. 전자종이는 전원을 끊어도 그림이 남아서 "1분마다 깨어나 시계를 고치고 다시 자는" 모드가 성립했다. LCD 는 전원을 끊는 순간 화면이 사라진다. 같은 것을 하려면 백라이트를 계속 켜 둬야 하고, 250mAh 로는 다섯 시간이면 끝난다.

그래서 상시 표시를 포기하고 손목시계처럼 만들었다. 평소에는 화면을 끄고, 집어 들면(BMI270 가속도) 켠다. 조작이 없으면 20초 뒤 어두워지고 45초 뒤 꺼진다. 라디오는 화면과 무관하게 계속 재생된다.

세 번째 버튼인 PWR 은 ESP32 핀에 붙어 있지 않다. PMIC(M5PM1)가 직접 보고 있어서, 꺼진 상태에서 누르면 레일을 올리고(= 부팅) 길게 누르면 강제로 내린다. 코드에서 이 버튼이 안 보이는 이유다. 굳이 읽고 싶으면 M5.BtnPWR 로 읽을 수는 있다. 다만 B 길게 2초 로 끄면 듣던 채널과 음량을 RTC 메모리에 적어 두고 잠드는 반면 PWR 로 끄면 그냥 전원이 끊기므로, 평소에는 B 로 끄는 편이 낫다.

"G3" 는 ESP32 의 GPIO3 이 아니다

공식 문서에 스피커 앰프(AW8737) enable 이 G3 로 적혀 있어 ESP32 핀으로 읽기 쉬운데, 실제로는 PMIC(M5PM1)의 GPIO3 이고 레지스터 0x11 의 bit3 으로 켠다. 소리가 안 나던 첫 원인이 이것이었다 — I2S 도 코덱도 정상인데 아무도 앰프를 켜 주지 않고 있었다. M5Unified 는 M5.Speaker 를 켤 때 같은 비트를 올리지만, 이 펌웨어는 I2S 를 오디오 라이브러리가 소유해야 해서 M5.Speaker 를 쓰지 않는다.

프로그램 구조

태스크 배치

전자종이 한 번 갱신에 0.36~1.4초가 걸린다. 그동안 오디오가 멈추면 소리가 끊기므로, 오디오를 더 높은 우선순위의 별도 태스크에 두고 화면은 낮은 우선순위에서 그린다. 화면을 그리는 도중에도 오디오 태스크가 선점해 버퍼를 채운다.

부팅 분기

딥슬립에서 깨어날 때 무엇이 깨웠는지에 따라 완전히 다른 경로로 간다. 타이머가 깨웠으면 Wi-Fi 도 오디오도 올리지 않고 시계만 고치고 다시 잠든다.

파일 구성

보드마다 다른 것(화면 · 핀맵 · 전원 관리)과 공통인 것(스트리밍 · 채널 · 코덱)을 디렉토리로 갈라 두었다. platformio.ini 의 build_src_filter 가 env 별로 common/ 과 해당 보드 디렉토리만 골라 컴파일하므로, 어느 한쪽을 손대도 다른 보드 펌웨어는 그대로 올라간다.

코덱 드라이버는 I2C 전송을 밖에서 받는다

es8311.cpp 는 두 보드가 공유하는데, 버스를 다루는 방법이 보드마다 다르다. ePaper 판은 Arduino Wire, StickS3 는 M5.In_I2C 다(이유는 겪은 함정). 그래서 드라이버가 버스를 직접 열지 않고, 읽기·쓰기·프로브 세 함수를 ES8311Bus 로 받는다. 기본값은 Wire 라 ePaper 판 코드는 달라진 것이 없다.

오디오 경로

ESP32-audioI2S 가 I2S 를 32bit 슬롯 · Philips · MCLK = 256×fs 로 잡는다. 리샘플링에 CPU 를 쓰지 않으려고 출력 샘플레이트는 스트림 원본을 그대로 따라가고, 값이 바뀔 때마다 ES8311 클럭 계수를 다시 계산한다.

ES8311 드라이버는 Espressif esp_codec_dev 의 레지스터 시퀀스에서 재생 경로만 남겨 옮긴 것이다. 코덱은 슬레이브, ESP32 가 I2S 마스터다.

Wi-Fi 모뎀 슬립은 상태별로 나눠 건다. 재생 중에는 끈다 — 스트리밍이라 무선이 어차피 자주 깨어 있어 절감폭이 작은 반면, 수신이 밀리면 버퍼가 마르고 소리가 끊긴다. 실측으로 버퍼 잔량이 20%에서 31%로 올라갔다. 일시정지 때는 켠다 — 트래픽이 없어 비콘 간격 내내 잘 수 있고, 여기가 실제로 크게 아끼는 구간이다.

빌드

pip install platformio
cp src/common/secrets.h.example src/common/secrets.h   # Wi-Fi 초기값

pio run -e epaper  -t upload             # ePaper 판, USB
pio run -e sticks3 -t upload             # M5StickS3, USB
pio run -e epaper-ota -t upload          # ePaper 판, 무선

pioarduino 플랫폼(Arduino 3.3.11 / ESP-IDF 5.5)을 쓴다. lib_ldf_mode 는 기본값이어야 한다 — deep+ 로 두면 내장 WiFi 가 의존하는 Network 라이브러리를 못 찾는다.

Windows 에서는 ESP-IDF 의 esp_matter 헤더 경로가 260자를 넘어 패키지 압축 해제가 깨진다. PlatformIO 홈을 짧은 경로로 옮기면 된다 (C:\pio 정션 + PLATFORMIO_CORE_DIR).

겪은 함정

같은 보드로 작업할 때 다시 밟기 쉬운 것들. 대부분 증상이 원인과 멀리 떨어진 곳에서 나타났다.

한 I2C 포트에 마스터 드라이버를 둘 올릴 수 없다

StickS3 에서 물렸다. M5Unified 는 PMIC 와 IMU 를 위해 내부 버스를 레거시 driver/i2c.h 로 잡는데, Arduino 3.x 의 Wire 는 ESP-IDF 5.5 의 새 i2c_master 드라이버를 쓴다. 같은 하드웨어 포트에 둘이 올라가면 나중 쪽 전송이 전부 ESP_ERR_INVALID_STATE(259)로 떨어진다. 

[E][esp32-hal-i2c-ng.c:372] i2c_master_transmit_receive failed: [259]
[E][Wire.cpp:532] requestFrom(): i2cWriteReadNonStop returned Error 259

증상이 셋으로 갈라져 나와서 오래 헤맸다 — 코덱을 못 찾고 (NO CODEC), 배터리가 -1% 로 찍히고, 그 탓에 오디오 태스크가 아예 뜨지 않아 버퍼가 0% 였다. 셋 다 버스 하나가 죽어서 생긴 결과다.

Wire.begin() 을 중복 호출하지 않게 고치는 것으로는 낫지 않는다. 원인은 호출 횟수가 아니라 드라이버가 둘이라는 것이다. 버스 주인을 하나로 정해야 한다 — StickS3 는 Wire 를 쓰지 않고 전부 M5.In_I2C 로 보낸다.

GPIO17 을 내리면 보드가 스스로 꺼진다

이름만 보고 “배터리 전압 측정용 분압 게이팅”으로 넘겼는데, 실제로는 배터리 전원 자체를 끊는 스위치였다. 딥슬립에 들어가며 이 핀을 내리면 보드가 자기 전원을 끊는다.

그런데 USB 가 꽂혀 있으면 USB 가 먹여 살려서 멀쩡하게 동작한다. 그래서 “USB 에서는 다 되는데 배터리에서는 시계 모드만 죽는다” 는 형태로 나타나고, 전원이 아닌 곳에서 원인을 찾게 된다.

USB CDC 출력이 오디오를 끊는다

HWCDC 는 호스트에 연결됐지만 아무도 포트를 읽지 않으면 링버퍼가 차고, write 한 번이 최대 2초(20회 × 100ms)까지 블로킹된다. 오디오 라이브러리 로그 콜백이 오디오 태스크에서 돌기 때문에 그동안 재생이 멈춘다.

배터리로만 돌 때는 호스트가 없어 즉시 버려지므로 증상이 없다. 그래서 “충전 중에만 주기적으로 끊긴다” 로 보인다. 해결은 Serial.setTxTimeoutMs(0) 와 로그 줄이기.

딥슬립 뒤 부분 갱신에는 기준 이미지가 필요하다

전자종이 부분 갱신은 컨트롤러 안의 이전 이미지와 새 이미지의 차분으로 동작한다. 평소에는 GxEPD2 가 알아서 맞춰 주지만, 딥슬립에서 깨어나면 하드웨어 리셋을 거쳐 이전 이미지가 남아 있다고 믿을 수 없다. 그대로 부분 갱신을 요청하면 화면이 아예 바뀌지 않는다.

직전 화면을 nextPageToPrevious() 로 다시 그려 넣으면 기준이 생겨 항상 정확해진다. 화면 전체를 보관할 필요는 없다 — 시각·온습도·배터리 20여 바이트면 같은 그림을 다시 그릴 수 있다.

딥슬립 기상은 ext1 이 낫다

ext0 는 RTC 주변장치 전원 도메인이 켜져 있어야 내부 풀업이 유지된다. esp_sleep_pd_config() 를 빠뜨리면 슬립 중 핀이 떠서 버튼을 눌러도 깨어나지 않는다. ext1 은 핀을 여러 개 볼 수 있어 버튼 두 개를 모두 기상 소스로 쓸 수 있고, 어느 핀이 깨웠는지도 알려준다.

딥슬립 전에 GPIO 를 gpio_hold_en 으로 붙잡되, 깨어난 뒤 반드시 풀어야 한다. 안 풀면 setup 의 digitalWrite 가 먹히지 않아 전원이 영영 안 켜진다.

뮤트는 전력을 아끼지 못한다

DAC 만 막을 뿐 Wi-Fi 수신과 디코딩이 그대로 돌아 전력의 대부분을 계속 먹는다. 아끼는 건 앰프 전류뿐이다. 그래서 이 펌웨어에는 뮤트가 없고 스트림 자체를 끊는 일시정지만 있다.

전자종이를 시간 기준으로 갱신할 이유가 없다

잔상은 부분 갱신이 쌓여서 생기는 것이지 시간이 지나서 생기는 게 아니다. 내용이 바뀌지 않으면 다시 그릴 필요가 없다.
